# MEGATARD Menu v1.1

Version 1.1 updates plugin discovery, saved script management and vehicle strength
controls. The EASY and HARD installers contain the same menu, binding metadata
and ScriptHookV-NX v1.4.1 Preview catalogue revision 1.

## Plugin management

The runtime catalogue grows through stable metadata pages, independently of the
configured resident-module limit. The menu caches eight visible row indices;
that window does not limit the number of installed plugins.

Rescanning first collects a complete directory snapshot, then reconciles existing
owners. Directory errors preserve the previous catalogue. A scan generation
distinguishes a queued request from completed discovery; it does not imply that
an Auto plugin has finished loading. Detail pages resolve the selected filename
identity again before acting. Startup suffix changes retain existing mappings.

Deleted unmapped entries are hidden and their unpublished slots can be reused.
Deleted resident entries remain visible because native handlers, callbacks and
suspended scripts may still reference their executable memory. Restart GTA to
replace resident code or recover its mapping budget.

## Saved NSC scripts

Saved names use namespaced SD records, with eight names per page and two cached
pages for the visible window. There is no fixed list or combined-character limit.
Individual normalized names retain the engine's 31-character representation.
Storage, representable indices and engine resources remain finite.

Each update prepares the inactive bank of the affected page or pages, then
publishes a root generation. Readers ignore prepared generations until the root
commits. Prepared buffers are invalidated even when a later write fails. The
runtime supplies CRC-checked alternating records for each namespace. This does
not establish resistance to arbitrary SD corruption or repeated media failures.

The former settings stream is retained for migration and recovery. Migration is
idempotent and records completion only after all prior names have been imported.
Removal swaps the final name into the removed row, avoiding rewrites of the
entire catalogue. Active custom threads are enumerated from the VM; saving more
names does not allocate more execution stacks.

The VM Stack Size counter calls `GET_NUMBER_OF_FREE_STACKS_OF_THIS_SIZE` for the
selected official pool. The launcher rechecks availability before starting a
script. Game scripts can consume capacity between the displayed count and launch.

## Vehicle controls

Acceleration Speed and Tyre Grip Strength use integer hundredths, 0.05 steps,
`Normal` at 1.00 and five-character numeric entry. Values clamp to 0.05–999.
Earlier saved selector values migrate without changing unrelated settings.

Acceleration changes torque, with the existing 72 m/s boost cutoff retained.
The train path retains its separate 120 m/s ceiling. These controls do not remove
the port's physics limits.

The previous grip implementation called `SET_VEHICLE_FRICTION_OVERRIDE`. Reviewed
engine source applies that value to collision contacts, rather than tyre
traction. The replacement uses the game's four reduced-grip levels below Normal
on cars and mass-scaled lateral assistance above Normal on grounded cars/bikes
controlled by the player. It avoids altering shared handling data, vertical
velocity, airborne vehicles and passenger-controlled vehicles. Strength values
are assistance settings, not literal multipliers of the tyre handling curve.
Normal restores reduced-grip state owned by the menu. Chaos Mod retains priority.

- [ ] Physical acceptance of the complete v1.1 menu/runtime pair.

The bundled checklist groups plugin rescanning, saved-name migration, stack
counts, keyboard controls and vehicle behavior in one session. Compilation,
native-table coverage, modeled ARM64 execution and archive readback are separate
from physical gameplay acceptance.
